# M4 接口实现对照

在「工程工作区」关联一份已确认设计并保存 Python 代码后，可以按快照查看 FastAPI 路由声明和设计契约的差异。对照使用工作区绑定的设计流程版本和所选不可变文件快照。升级沿用现有数据库和工程快照，本版无需新增迁移。

## 页面操作

1. 打开「工程工作区」，选择关联了已确认设计的 Python 工作区。先保存代码候选或手工保存完整文件快照。
2. 在「接口实现对照」选择「对照代码快照」。默认使用最新已保存快照，也可以选历史版本。面板显示设计流程版本与文件快照摘要。
3. 查看结果状态。展开「设计契约」核对已确认字段，展开「代码证据」查看快照内的文件、行号、处理函数、声明片段和文件摘要。
4. 展开「同一快照的测试记录」查看关联的隔离执行状态与测试数量。执行详细日志仍在「真实执行记录」。保存新版本后，历史快照及其测试记录仍可回查。

| 状态 | 含义 |
|---|---|
| 一致 | 方法、路径以及设计中本版可核对的声明字段相同。 |
| 实现新增 | 快照声明了一个已确认 HTTP 清单未列出的方法和路径组合。 |
| 设计接口缺失 | 在当前支持的静态注册方式中未发现该设计声明。 |
| 契约变更 | 方法和路径相同，可对照的声明字段有差异。 |
| 待核实 | 涉及未解析的注册、设计契约缺少结构化字段、重复声明或需要更多契约证据。 |

## 静态分析边界

- 识别从 FastAPI 导入并在模块顶层直接赋值的单个应用实例，以及同文件顶层函数上的 `@app.get`、`@app.post` 等装饰器。`@app.api_route` 需要写明字面路径和方法列表。
- HTTP 方法与完整路径组成对照键。路径不同会分别显示旧设计缺失和新实现新增，保留前后两条证据供审阅。
- 已确认设计可用 `contract.method`、`contract.path` 声明 HTTP 接口。可选 `status_code` 和 `response_model` 比较代码中显式的状态码和响应模型名称。请求体结构、响应模型字段、动态注册、多应用及路由前缀解析属于后续范围。
- 静态扫描只读取保存的文本。路由包含、动态声明及解析失败有诊断时，未匹配到的设计项显示「待核实」。历史设计只有说明文本时，已找到的实现项同样可供查看和核实。
- 实际运行的 HTTP 接口和状态仍由运行证据或测试确认。隔离采集 OpenAPI 是后续扩展。对照为只读查询，需要发布知识修订时继续走现有提案流程。

## 选课三轮验收

使用「校园选课系统 · 三轮复验」中已确认的 `POST /enroll` 设计。为每轮选择关联该设计的工作区，将 [选课 FastAPI 入口](../examples/course-selection/app.py) 作为根目录的 `app.py` 和本轮 `course_app.py`、`test_course_app.py` 一并保存。也可从已有的选课快照创建工作区后再添加 `app.py`。教学版入口可以通过 `uvicorn app:app` 启动。

| 工作区 | 业务变化 | 接口核对 |
|---|---|---|
| M4 · 基础选课 | 首次选课和重复请求 | `POST /enroll` 一致，证据为 `app.py` 中的 `enroll`。 |
| M4 · 容量限制 | 满员返回 409，重复请求仍成功 | 接口方法和路径仍一致。 |
| M4 · 时间冲突 | 重叠课表返回 409，相邻课程可选 | 接口方法和路径仍一致。 |
| M4 · 接口路径差异 | 在独立工作区把装饰器的路径改成 `/enrollments` | 设计中的 `POST /enroll` 显示缺失，`POST /enrollments` 显示新增并可展开代码证据。切回初始快照应显示一致。 |

## API

- `GET /engineering/workspaces/{workspace_id}/snapshots` 列出该工作区可选的快照版本及摘要。
- `GET /engineering/workspaces/{workspace_id}/snapshots/{snapshot_id}/interface-comparison` 固定到该快照并读取对照结果、诊断和同一快照的执行摘要。
