# M2 知识增量、冲突审阅与影响追溯

M2 延续「原文 → 模型候选 → 人工审阅 → 知识提案」流程，把本轮变化、身份匹配和影响依据集中在抽取页面。模型可以建议相同性或冲突，正式写入仍由审阅人选择、校验和确认。继续使用现有 PostgreSQL、FastAPI、Vue 与 Mermaid，不新增向量数据库或图形平台。

## 页面操作

1. 进入「项目知识 → 文档知识抽取」，登记原文或选择已有来源的新版本。
2. 选择「原文范围」。**完整文档**会提示同来源已确认但本轮未纳入的知识及关系；**增量补充**只审阅本次内容，不因旧内容未再次出现而提示移除。
3. 发起模型抽取。逐项核对候选及原文引文，修正名称、说明、验收条件，选择是否关联已有知识。
4. 点击「分析本轮增量与影响」。查看修改前后内容，区分新增、修订与「内容沿用，补充证据」。只是新增证据仍产生不可变知识修订，但不会被当作业务内容变化传播影响。
5. 在「逐项处理重复、冲突和缺失提示」中作出选择并填写依据。
   - 若为同一对象，点击「在候选中关联此已有知识并重新分析」，确认复用该身份。不同来源可以绑定到同一个知识 ID；已有来源的稳定键不能换绑。
   - 若同名但业务身份不同，说明保留独立对象的业务范围。
   - 冲突提示同时展示本轮引文及已有知识固定版本中的引文。修改同一知识时明确确认修改；保留不同对象时说明各自的适用范围。此判断不会自动建立或解除正式冲突关系。
   - 验收条件被删改时核对范围。旧知识或关系缺失时选择保留，或记录移除建议，另行提出生命周期修订。
6. 展开「潜在影响与追溯路径」，查看需求、规则、架构组件、接口、代码或测试的固定引用路径。已有项目基线中的架构节点、业务流程和场景只按明确引用列出。标记为潜在影响不代表产物已经修改。
7. 处理全部检查项，填写总体审阅依据并勾选确认，建立提案。进入原「项目提案」页面，复核保存的增量报告，依次「校验当前提案」「确认提交当前提案」。

修改候选、已有身份绑定或选择范围后，旧分析作废，需要重新分析。修改某项处理依据后，需要重新勾选最终确认。模型完成、分析完成及校验成功都不会代替确认提交。

若模型未提取到新知识，仍可分析完整文档中的缺失项。只有移除建议时不能建立空写入提案；可从「项目知识 → 修订此知识」另提生命周期变更。这里的移除建议不等于物理删除，也不会级联删除历史关系、证据、设计或工程快照。

## 检查分别由谁完成

| 内容 | 实现与适用边界 |
|---|---|
| 已确认身份延续 | 来源绑定及固定 ID／版本校验，不按名称换身份。 |
| 有界召回 | 保留同来源绑定，按中文二元词和英文词面重叠召回其他知识。页面显示纳入及遗漏数量。 |
| 相似候选 | 同名／近名规则提供线索；模型根据范围、含义与证据提出语义匹配建议。都需要人工确认。 |
| 语义冲突 | 模型比较当前原文与已有知识，给出两侧引文及理由；服务端校验引文存在和版本，不宣称自动证明语义冲突。 |
| 确定性检查 | 比较名称、说明、属性、验收条件及关系版本；检查显式冲突、跨来源绑定、完整文档遗漏。 |
| 影响追溯 | 在任务开始时冻结的关系图谱上按方向遍历，保存解释路径，不让模型猜测代码已变或测试已执行。 |

检索上限：词面候选池最多 2000 条，通常纳入最多 80 条完整知识；同来源已绑定知识优先保留，最多 200 条，必要时超过通常的 80 条配额。纳入知识间的关系超过 400 条会明确拒绝。影响快照最多 2000 个非证据知识对象、4000 条有效关系，默认展开 4 层和 200 个对象。截断或缺失起点会明确提示；未发现冲突不等于已排除全项目冲突。

相同／相近名称的每个候选最多展示 5 条已有匹配线索，本轮同名候选按组提示。超过 500 项检查时明确拒绝，要求缩小范围，不静默丢弃检查项。模型对业务自定义扩展仍可读取；大段历史审计、影响图谱和证据重复正文不发送给模型。

## 固定版本与审计

抽取任务保存原文、召回知识、关系、影响图谱、项目架构基线和模型交互。语义建议使用已有知识 ID、版本及逐字引文引用比较对象。服务端按当前候选重算报告摘要，客户端不能通过删掉模型提示或提交旧摘要绕过审阅。

提案保存完整报告、每项处理选择、依据和署名。提案生成及确认提交都会核对任务开始时的项目知识头版本和项目基线；有新知识或关系修订时，拒绝沿用旧分析，要求重新抽取。这是保守的项目级保护，当前不自动判断其他变更是否与本轮无关，也不自动合并版本冲突。

旧 M1 已提交记录保持原样。旧任务仍可做确定性比较，但页面会说明它没有执行 M2 模型语义检查，也没有当时的影响图谱快照，不把当前图谱回填成历史事实。正式知识修订、原文及历史审阅记录仍不可覆盖。

## 接口变化

| 接口 | 新增内容 |
|---|---|
| `POST /extractions/projects/{project_id}/jobs` | `source_scope: full / delta`，默认 `full`。任务上下文记录审阅协议版本、召回范围与固定影响快照。 |
| `POST /extractions/jobs/{id}/review` | 输入 `{candidate}`；只读返回变化、检查项、影响路径、范围及 `review_digest`。 |
| `POST /extractions/jobs/{id}/proposals` | 除原有字段外提交 `review_digest` 和 `decisions: [{finding_id, action, reason}]`。缺项、无依据、候选改动或版本过期会拒绝。 |
| `GET /workbench/proposals/{id}/diff` | 提供 `extraction_review` 保存的只读报告，不依赖之后的图谱重算。 |

复用现有不可变任务及提案 JSON 记录，本轮无需新增数据库迁移。升级需要更新后端并重建前端。旧版客户端需要先调用增量分析接口再建立新的抽取提案；历史提案原有审阅操作保持兼容。

## 选课验收

1. 使用 [跨文档重述](../examples/m2-course/01-跨文档重述.md) 与已有重复请求规则比较：语义和文字一致时确认同一身份，结果应为补证据且无业务影响起点。
2. 使用 [模拟冲突草案](../examples/m2-course/02-模拟冲突草案.md)：检测“满员仍复用原记录”和“满员拒绝重复提交”的差异，未处理时不能建立提案。该草案用于验收，不代表采纳新的选课业务政策。
3. 使用 [容量并发影响草案](../examples/m2-course/03-容量并发影响草案.md) 与已有架构、流程、代码及测试关联比较，检查影响路径与固定版本。保留为待审产物，不自动修改工程文件或运行测试。
4. 用完整与增量两种范围对比遗漏行为；回查此前的知识、来源和架构基线，确认旧版本仍可打开。

实际本机结果见 [M2 验收记录](m2-acceptance-report.md)。本轮不交付架构或 UML 图上变化叠加；这些视图将使用固定身份与版本在 M3 实现。行为及质量模型试点仍按演进文档的顺序推进，尚未进入持续知识演进阶段。
