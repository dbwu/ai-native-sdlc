# 由模型分析项目架构和业务图

每轮先在「项目知识」录入需求并确认提案，再在「需求设计」绑定本轮和继续生效的需求版本。确认设计后，可在「项目知识 → 项目架构与业务流程 → 建立项目基线提案」选择「从已确认设计生成项目基线」。选中本轮设计，填写署名，点击「模型生成基线提案」。

服务发送固定需求、规则、已确认设计、设计产物标识以及前一版项目基线。模型提出领域、模块职责、协作、泳道步骤、分支和时序消息。模块是否拆分取决于职责、接口和事务边界。新增规则可以由原模块承接，并在流程和时序中增加步骤。原有节点、流程和消息使用稳定标识做版本对照。

项目提案页可选择预览逻辑结构、接口与协作、泳道图和时序图，并展开「查看发送给模型的输入和模型回复」。先校验再确认提交。确认后，「项目知识」和 Markdown 记录来源模型、设计版本与模型输出摘要。需求级用例图、职责图、协作图、时序图继续来自「需求设计」中经过审阅的模型输出。Mermaid 将已校验的结构渲染为图。

## 用选课验收

1. 在新项目中录入[基础选课需求](../examples/m1-course/01-基础选课.md)，生成并审阅设计。检查首次提交和重复提交的处理。
2. 用该设计建立项目基线并审阅发布。此时可看项目架构、协作、泳道和时序，以及需求级用例图。
3. 录入[容量限制](../examples/m1-course/02-增加容量限制.md)，绑定仍有效的基础需求生成下一轮设计和基线。检查满员及零容量拒绝、重复提交仍返回原记录。
4. 录入[时间冲突](../examples/m1-course/03-增加时间冲突.md)，绑定三轮需求后生成设计和基线。检查重叠拒绝、相邻时段允许及拒绝后记录不变。在「版本对照」核对新增分支和消息、模块归属与旧图。

开发验证可沿用[本机 Codex 模型连接](m1-knowledge-extraction.md#启动与模型选择)。生产环境继续使用已配置的模型服务。本版复用现有提案和项目基线存储，升级沿用现有数据库结构。
