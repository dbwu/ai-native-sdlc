# 中文 SDLC 验证工作台使用说明

工作台让你通过页面逐步验证需求、架构、代码和测试之间的知识流转。当前使用明确标注的订单取消参考场景；不需要接大模型，也不会将任意业务需求自动转换成对应代码或修改用户业务仓库。

## 打开工作台

启动本地服务后，访问：

[http://127.0.0.1:8000/workbench/](http://127.0.0.1:8000/workbench/)

如果使用 Docker Compose，在项目根目录运行：

```sh
docker compose up -d --build
```

已有容器需重新构建 API 镜像，才能加载新增页面。镜像构建会生成 Vue 工作台资源，正常使用不需要另外运行 Node 或前端开发服务。等待服务就绪后打开工作台；原来的 [接口文档](http://127.0.0.1:8000/docs)继续保留。

原生 Python 启动仍使用项目既有流程：设置 `DATABASE_URL`，执行 `python -m knowledge.db`，再启动 `python -m uvicorn knowledge.api:app --host 127.0.0.1 --port 8000`。页面与 API 使用同一服务地址。从源码目录启动时，应先确保 `knowledge/web/` 中已有前端构建产物；使用包含静态资源的安装包则无需本机 Node。

工作台通过 Vue Router 提供多页导航，切换页面时保留所选项目和流程。地址中的 `#` 后部分是前端页面位置；刷新或直接打开页面仍使用同一个 `/workbench/` 入口。

如果你需要修改前端源码，先准备 Node.js 与 npm，再在 `frontend/` 中执行：

```sh
npm ci
npm run build
```

源码采用 Vue 3 与 TypeScript，构建结果位于 `knowledge/web/`。不要直接改生成的静态文件；完成构建后再启动或重新加载 Python 服务。仅使用工作台时不需要执行这些前端开发命令。

## 新建一次独立验证

1. 选择已有项目，或新建一个专门用于验证的项目。
2. 创建新流程，填写标题和本次验证目标，明确选择订单取消参考场景。
3. 填写操作署名和理由，便于之后区分每一次审核与推进记录。
4. 查看初始化提案：系统准备的是尚未完成的知识占位产物，不代表已经生成并验证代码。
5. 校验初始化提案，确认内容后提交，再启动流程。

署名仅是本地记录，不是经过认证的用户身份。建议使用独立验证项目，避免把参考业务内容与日后真实工程知识混在一起。

## 逐阶段运行与审阅

四个阶段依次为需求分析、架构设计、代码实现和测试验证。页面会显示当前步骤、可执行动作，以及暂不能操作的原因。主流程不需要你填写 UUID、拼接 JSON 或管理执行租约。

每个阶段按下面的顺序操作：

1. **运行参考 Agent**：只运行当前阶段，读取固定版本上下文并形成待审产物。验证阶段会调用服务端可信执行器，实际运行内置测试。
2. **查看产物与差异**：核对需求验收条件、架构内容、源码或测试内容。差异中的旧内容来自提案原始基线，不一定是此刻最新版本。
3. **校验与确认提交**：校验通过后，亲自决定是否提交知识提案。校验通过不会自动完成审批。
4. **完成任务**：根据页面提示确认阶段任务。有关联知识提案时，需先完成其提交。
5. **生成并确认阶段门禁**：审阅阶段输出状态及追溯关系的变化，校验并提交另一份门禁提案。
6. **阶段放行**：推进到下一阶段。下一任务在这时使用新近确认的知识版本创建。

两个确认层次各有用途：产物提案确认具体知识修改，阶段门禁确认这些产物是否可以成为后续阶段依据。工作台会展示当前需要审阅的那一份提案。

## 查看真实测试与追溯

测试与证据区域可查看测试数量、结果、退出码、日志以及代码和测试内容摘要。参考场景包含四项独立测试：未支付订单取消、已支付订单拒绝、重复取消幂等，以及不同订单的状态隔离。

最终阶段门禁通过后，需求的实现和验证关系可显示为已验证，并固定引用对应代码、测试和证据版本。“已验证”不是把任意旧测试报告用于新代码；内容或版本不一致时流程会提示冲突。

参考代码和测试是在临时目录实际执行的，源码文本、摘要和结果用于追溯。它不证明真实业务仓库或生产环境已经通过测试。

## 拒绝、重试与冲突

- **拒绝提案**：保留拒绝原因和历史。既有提案不能原地改写，后续使用新修订或新的阶段尝试。
- **初始化被拒绝**：取消不再使用的草稿流程，用明确的新定义创建流程。
- **退回当前阶段**：按页面提示结束旧尝试并重试。若旧产物已经提交，可能先需要人工确认关系版本对齐提案。
- **版本冲突**：刷新查看最新内容，再决定如何处理。页面不会自动改版本号重试提交。
- **暂停**：暂停流程推进，不表示已经中断运行中的任务。
- **取消**：终止流程，并按原有规则取消当前尚未结束的任务。已提交知识不会被自动回滚。
- **错误或阻塞**：读取具体诊断，不把请求成功返回或校验完成视为阶段通过。

再次打开页面后，流程、提案、产物和历史从后端读取。刷新页面不应被理解为重新执行或重新批准已有动作。

## 当前模式与后续阶段

当前为参考模式，没有外部大模型调用，不需要填写模型密钥。名称与目标用于记录本次流程；修改它们不会改变内置订单取消业务逻辑。

工作台用于先验证前四阶段的操作体验。本轮不实施持续知识演进。真实模型、业务仓库和 CI 接入后，产物来源与执行方式会扩展；项目、流程、提案、代码和证据的基本查看与审阅方式可以继续沿用。

页面中更详细的字段含义和版本规则可查看[第四阶段设计](phase4-design.md)；各轮已完成检查见[验证记录](verification.md)。
